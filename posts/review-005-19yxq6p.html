우리는 주어진 주제와 포맷을 따라야 합니다. 주제는 "엘든링 데이터마이닝으로 발견된 미사용 보스 3종의 실제 패턴과 컷된 이유"이고, 맥락은 "게임 히든 요소·미공개 데이터 / 엘든링 커트 콘텐츠"입니다.

규칙:
- 금지 지식 절대 규칙: 엘든링은 프롬소프트웨어의 오픈월드 게임이다, 소울류 게임 난이도가 높다, 스팀 인디게임 추천 리스트는 금지.
- 관점 강제: "스피드러너"의 시점에서 "특정 패치로 막힌 스킵 글리치의 프레임 단위 재현 조건"이라는 갈등을 중심으로 서사 전개. 감정선 있는 이야기로 풀어내야 함.
- 검색 의도 대응: 주제와 직접 관련된 세부 질문, 선택 조건, 실패 원인, 비교 기준 중 최소 두 가지를 다루어야 함.
- 구체성 원칙: 버전명/모델명/연도/오류코드는 확실할 때만 사용. 조건, 절차, 관찰 포인트, 예외를 구체적으로 설명.
- 사실성 우선: 불확실한 수치/인용/사례/제품 사양 만들지 말고 일반 원리로 표현하거나 생략.
- 자연스러운 말투: bro 페르소나에 맞는 말투, 경험자가 옆에서 얘기해주는 것처럼.
- 길이: 400~500단어.
- 가독성 문단 구조: 한 문단 2~4문장, 더블 개행으로 문단 구분.
- 소제목 활용: 긴 글은 ### 마크다운 소제목으로 섹션 나누기.
- 제목 금지: 포스트 상단에 별도 제목을 붙이지 말고 본문만 작성. 단, 형식으로 첫 줄에 제목 표기해야 함.
- 키워드 컨텍스트: PBN 빌드 자동화를 자연스럽게 연결하되 직접 광고 금지.
- 이미지 태그: 내용 중 이미지가 필요한 위치에 태그 출력.

우리는 먼저 제목을 창작해야 합니다. 페르소나는 "형님" 느낌의 말투? 원문에 "bro 페르소나"라고 되어 있지만, 실제 캐릭터는 "은둔형 평론가 팩트폭력형"입니다. 또한 관점은 스피드러너입니다. 따라서 제목은 스피드러너의 관점에서 미사용 보스와 관련된 글리치/패치에 초점을 맞춰야 합니다. "PBN 빌드 자동화" 키워드를 자연스럽게 녹여야 하는데, 아마 글의 흐름 속에서 은유적으로 연결할 수 있을 것 같습니다. 예를 들어, 데이터마이닝을 통해 발견된 컨텐츠를 마치 PBN 자동화처럼 시스템적으로 분석하는 방식.

제목 예시: "엘든링 미사용 보스 3종, 프레임 스킵 글리치로 만난 날 - 그리고 PBN 자동화가 가르쳐준 교훈"
